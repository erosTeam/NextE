# 产品修改与验收

权限规则只见 [始终生效规则](always-loaded-rules.md)；本文件规定实现和普通使用验证。

## 修改前

- 写清用户原问题、原正常行为、允许改变的属性及一条普通用户路径；标准不能从补丁倒推。
- 查当前源码、提交和数据所有权。参考 `eros_fe`/V2Next/HDS 时读完整父树，不用别的产品替代 NextE 事实。
- 追调用者、写入者、异步回调、父级/相邻状态、全部适用宿主和保留旧版路径；文件未改不等于不受影响。
- 涉及产品语义、数据归属、同步/远端结构、不可逆动作或未授权界面变化，先给出具体差异，由用户决定。

## 实现

- 针对有证据的错误，不顺手重做 UI、parser、持久化和状态所有权。
- 字段统一定义语义、来源、存储、同步与展示；禁止单设备镜像字段绕过迁移。
- 分页、刷新和缓存各司其职：查询有界、增量加载，刷新或失败保留最后可展示内容。
- 同类页面复用现有结构；EH 账号、Cookie 和远端写入遵循 [EH 协议](../eh-integration-contract.md)。

## 实际使用验证

- 从普通入口操作，覆盖进入、加载/切换、现有动作、返回和持久结果。缓存、空数据、失败、键盘、长文本等按真实影响选择，不为凑次数扩矩阵。
- 当前构建、前台 App、设备型号、方向/折叠状态及有效窗口必须明确；不同状态不能互相映射几何。
- 先顺序看原片，记录全部消失、遮挡、跳变、错位、变形、闪烁和背景缺失，再看日志/实现解释。
- 转场看完整背景、运动主体、相邻控件、系统栏，以及运动结束到真实组件出现的交接；不能只看终点或修过的元素。
- 联系表只定位问题。涉及位置/形状时回看原分辨率帧和布局；“大致接近”不算通过。
- 一个可见反例否决相关通过结论；用户从原片指出异常，先撤回结论并重新判读该原片。
- 日志证明状态链，画面证明可见结果，构建证明构建；互不替代。未验证写未验证，不声称已修好。
- 既有证据仅覆盖原版本、环境、路径和有效依赖；新反馈或相关依赖变化才重开，不重跑未变路径制造进展。
- 外发、付费和不可逆提交遵守已有具体授权及数量限制；没有授权就验证到本地无害边界。

## 记录

- 一个任务一个当前记录：范围、实际结果、未完成项和下一动作，就地更新。
- 闭环放 `completed/`；被替代、停用或仅供查证的材料放 `archive/`。归档先保留仍未完成动作。
- 长期规则只写对应指南；不维护追加式全局事故/dispatch 账本。原始证据本地保存，技术设计不重复进执行规则。
