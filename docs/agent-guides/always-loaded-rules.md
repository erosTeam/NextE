# NextE 始终生效规则

这里只保留所有任务都适用的跨领域边界。ArkTS/UI、产品、EH、设备和本地构建细则由
[AGENTS.md](../../AGENTS.md) 分流到对应文档，不在这里重复。

## 权限与范围

- 用户最新明确请求决定当前任务。历史计划、归档、证据、handoff、租约和遗留工作区都不能自行
  创建任务、扩大范围或授权设备/远端操作。
- 可以自行处理不改变确认结果的可逆实现细节。涉及产品语义、数据归属、远端表结构、用户可见
  信息层级、不可逆行为或其他重大取舍时，先说明冲突、收益和代价，等待用户决策。
- 用户在任务中补充问题时，继续完成尚未取消的原目标；如果新请求明确替换旧目标，再停止旧目标。
- 不以“避免修改某层”为默认最高优先级。边界冲突必须按用户目标、数据一致性和当前架构共同评估，
  不能私自绕过后再让用户承担返工。

## 流程与技能

- 流程规范是正确性的一部分，优先于临时操作效率。任务顺序必须是：确认当前目标、读取适用
  skill/领域指南、检索相关记忆和当前任务产物、核对源码与新证据、形成计划、再执行；不得先行动
  后补读规范。
- 当前任务命中的 skill 是执行流程，不是可选参考。必须在行动前完整读取，并在实际决策、命令和
  验收中继续遵守；不能读完后改走临时自创流程。
- Skill 约束“如何执行”，不能自行扩大“做什么”或“操作谁”。它不创建用户授权；与用户当前明确
  范围冲突时，先服从用户范围，再在该范围内执行适用流程。
- 多个 skill 或指南同时适用时，按 `AGENTS.md` 的权威顺序和更具体的场景规则组合执行。不得因为
  另一工具更方便、证据更多或临时分析看似更快，就绕过直接约束当前场景的流程。
- 每个新目标开始或适用规范发生变化时完整读取，读完即进入执行。同一未完成目标中的用户纠正、
  重试、上下文压缩或工具失败不构成新任务，不得因此反复重读规范来代替行动或制造等待；只有被
  引用的必读资料、规范版本变化或实际冲突才触发增量补读。
- 规则违反后先恢复到最后有效状态并按原流程继续，不用更多解释、临时步骤或新流程覆盖既有规范。

## 记忆与任务连续性

- 非平凡任务、重复验证、历史回归或用户要求保持一致性时，计划前先做与当前关键词直接相关的
  记忆检索；已有可靠协议或任务产物时继续复用，不以“重新分析更保险”为由从零开始。
- 记忆负责定位既有决策、已证明路径和最后有效状态，不创造任务、授权或当前事实。设备在线状态、
  远端内容、源码和工作区等易漂移信息仍以实时检查为准；记忆与当前证据冲突时，以当前证据为准并
  明确旧信息已过期。
- 用户对当前复现或验证的纠正默认是原场景的增量。只废弃被否定的动作、样本和结论；其余已证明
  前置条件继续有效。只有用户改变目标、明确否定前置状态或新证据证明其漂移时才重新建立。
- 上下文压缩、任务中断和重试都不清空状态。交接信息必须保留：当前目标、已确认事实、被否定样本、
  未提交改动、最后有效检查点和下一步，不重复已经完成或被否定的探索。
- 只有用户明确要求更新记忆时才写记忆增量。更新应短小，记录可复用规则、当前验收状态和恢复点；
  不把一次对话叙事、敏感内容或易漂移的完整设备地址写成长期事实。

## 证据与完成边界

- 未知事实先变成证据。远端协议、页面 DOM、账号/资产/配额、数据同步、用户可见状态和平台 API
  不得靠猜测推进实现。
- 先查当前源码、提交历史和真实数据流，再改代码。参考项目提供语义或平台写法，不能替代 NextE
  当前实现证据。
- 构建、静态检查和代码存在只证明实现候选；设备截图、布局、日志、fixture 或真实用户路径才证明
  对应运行时行为。缺少黑盒证据时使用 `implemented candidate / needs QA`，不能宣称完成。
- 诊断任务只定位原因和证据；除非用户同时要求修复，不扩大为实现。
- 连续修补仍不能跑通时，停止叠加 workaround，回到状态所有权、数据流和最小可复现路径。

## Contract 使用边界

Contract 只保护会造成严重后果的稳定边界，例如：V2 状态管理、架构依赖、安全/凭据、远端写入、
同步与持久化数据完整性、真实 fixture 支撑的高风险协议/parser、设备互斥、版本/签名一致性。

不得为 UI 形状、布局、文案、视觉偏好、单次事故、临时 workaround、grounding 或普通验收流程新增
正则门禁。新增 contract 前必须能说明严重后果、现有验证为什么覆盖不了、失败后的修复方向；否则
使用源码审查、日志、截图、构建或设备路径验证。

不得因为 Agent 没有遵守已有 skill、指南或任务状态而新增脚本门禁、强制清单、命令拦截或
Contract。此类问题必须通过正确执行现有规范、保留已知状态和增量纠错解决，不能把判断责任转移给
新的机械限制。

## 仓库与提交

- 工作区已有改动属于用户。只改当前范围，保留无关 WIP；无法避开重叠时停下说明。
- 未经明确要求不提交、不推送、不建标签、不合并、不清理 worktree。
- 用户要求提交时，只暂存当前已确认并验证的路径；提交信息使用英文 Conventional Commits，敏感值
  不得进入提交信息、日志或 diff。
- 不使用破坏性 Git 命令覆盖用户改动。文档写着“已完成”不等于可以删除源码、文件或历史资产。

## 本地警示资料

`docs/agent-guides/incidents/` 只存本地开发警示，由 Git 忽略。受版本控制的文件不得链接、索引或
点名其中的具体文件，也不得 force-add 该目录。本地索引如有需要，只能保存在该忽略目录内部。

## 纠错输出

发生误改或规则违反时，不用口头保证替代行动。只报告：已经采取的具体动作、对应文件或规则、
验证结果、仍存在的阻塞，以及可以继续执行的最后有效状态。不得用一次失败把整个任务状态清零。
