# NextE 始终生效规则

## 不得擅改

**未经用户明确允许，禁止更改样式；修 bug 也不例外。**

- 修复保留原功能、样式和操作；不能靠删除功能、换效果或绕过故障使现象消失。
- 临时测试结束后恢复临时代码和设备设置；不得擅自保留改动。
- 用户未反对、默认设备测试、持续工作、官方 API 或测试通过，都不授权更改样式。
- 改错立即停止错误方向，撤回本轮改动，保留失败证据；原问题没有解决就仍未完成。

## 当前任务

- 用户最新明确要求优先。旧计划、摘要、记忆、租约和自动唤醒不产生新任务或授权。
- 已有授权持续有效；纠正、压缩和工具失败不清空任务。回应用户后继续未取消目标的下一安全动作。
- 一个分支缺条件只限制该分支；等待必须写明具体缺什么、恢复条件及仍可继续的动作。
- 先读适用技能和领域指南，查相关记忆、当前源码、工作区与实际证据，再执行。同一目标不反复重读代替工作。
- 记忆和历史用于定位，易变化事实实时核实；冲突时纠正旧信息，不从摘要自行补全授权。

## 设备执行环境

- 所有 HDC 命令（list targets、tconn、install、aa、uitest、hilog、file recv 等）必须在沙盒外的宿主环境执行。沙盒的网络限制会让 HDC 报 Connect server failed、ping 超时或空输出，这都不是设备离线证据。
- HDC 空输出、失败探针或沙箱网络错误不是设备离线证据。先确认允许的宿主执行方式，再记录实际失败与恢复动作。
- 报告设备离线或断开之前，必须先确认该命令已在沙盒外执行过；仅在沙盒内失败不得据此下结论。

## 修改与证据

- 先查旧行为、状态所有者、全部写入/失效路径、异步顺序和实际消费者。原因未知写未知，不叠加 workaround。
- 每次修改和提交前审精确 diff：只处理用户要求的问题，保护用户数据、无关 WIP 和原始素材。
- 受影响的普通用户路径分别验证。构建只证明构建；脚本、日志、截图和代理报告不能代替完整使用结果。
- 画面先按时间顺序寻找异常，再对齐代码。一个可见反例否决相关通过结论；数量、哈希或成功帧不能抵消失败。
- 具体 UI 判读与验收见 [产品规则](product-work.md)；平台实现见 [HarmonyOS](harmonyos-default.md)。
- 原图/录像留本地；当前状态就地更新，历史另存。交接保留原目标、用户限制、失败、WIP、源码/设备恢复结果及下一动作。
- 工具拒绝时检查安全替代，不绕过平台拒绝或修改安全机制；不把失败命令当产品结论或整个目标终止依据。

## 脚本与仓库

- Contract 只保护 V2、架构、安全/凭据、同步/持久数据、高风险真实协议、设备互斥和版本签名等严重边界。
- 禁止为视觉偏好、单次事故或未遵守规则新增 UI 正则、脚本门禁、hook、命令拦截或机械清单。
- 未经明确要求不提交、不推送、不建标签、不合并、不清理工作树。禁止破坏性 Git 覆盖用户改动。
- 用户要求提交时只暂存对应已审路径，英文 Conventional Commits；秘密不进消息、日志、diff 或提交。
- 本地事故目录 `docs/agent-guides/incidents/` 继续忽略；受控文件不得链接其具体文件，不得 force-add。

## 事实与复盘

- 只以可见用户原文和实际取得的记录说明指令、行为与原因；不得从质问、摘要或记忆补造对话。
- 区分原文事实、工具事实、推断和未知。推断标明依据；不能把客户端显示推成模型收到，也不能把时间先后写成因果。
- 错把推断写成事实时明确撤回，不用新猜测解释旧猜测。复盘报告实际影响、撤回动作、证据和仍未解决的问题。
