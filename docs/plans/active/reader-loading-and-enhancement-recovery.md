## 要解决的三个问题

### A. NextN 切换超分后当前页黑屏

在 Reader 设置中开启、关闭或切换超分配置时，当前图片会消失；需要翻页再返回才能恢复。
正确结果是当前页保持可见，并在新的超分结果可用后原位更新，不要求用户翻页。

### B. NextN 缩略图转场期间没有既有图片加载进度

从画廊缩略图进入 Reader 后，大图尚未加载完成时，NextN 没有呈现与 NextE 一致的完整 Reader
状态：既有图片加载进度和可操作阅读框架没有及时接管。该问题是 NextN 的行为回归，不是新增一个
加载组件的需求。

### C. 转场场景中的既有加载指示器辨识度不足

NextE 已有加载指示器，但在转场缩略图上不够清楚；NextN 在问题 B 修复后应使用同一类既有指示器。
需要给现有 `ReaderLoadingStage` 增加可选的转场背景，而不是创建第二套加载指示器。非转场调用必须
保持原样。

## 已确认的代码事实与尚未确认的原因

### 已确认

- NextE 与 NextN 都已经有 `ReaderLoadingStage`；问题 B 不是缺少组件定义。
- NextN 的多个 Reader 图片叶组件在内部 `enhancementEnabled`、`enhancementModel` 或
  `enhancementMaxHeight` 变化后调用完整的 `loadImage()`。
- NextN 的 `loadImage()` 会在重新加载开始时清空 `imageSource`、复位图片加载状态和部分页面状态。
  这条现有调用链能够直接解释问题 A 的黑屏。
- NextE 的图片叶组件保留 `resolvedFilePath` 和 `resolvedDisplayUri`；超分设置变化时先保留原始
  显示 URI，再重新执行增强，不清空当前图片。
- NextN 的 Reader 根层同时存在初始化用的 `ReaderLoadingState` 和图片加载用的
  `ReaderLoadingStage`。两者职责不同，不能再增加第三个根层覆盖指示器。
- 问题 A、B 只允许修改 NextN。NextE 在这两项中只作为只读行为参照。
- 问题 C 才涉及 NextE 与 NextN 两边的既有加载组件。

### 尚未确认

- 问题 B 的第一处退化提交及唯一根因尚未确认。当前两边在 Reader 根层组合顺序、
  `isReaderReadyForCurrentGallery` 门控和打开代理所有权上存在差异，但不能在没有历史差分与实机证据时
  把其中任意一项直接宣布为根因。
- 问题 C 的最终尺寸、透明度和模糊强度必须由 237 的完整加载过程确认，不能只看稳定态截图或源码数值。

## 阶段 1：只修 NextN 切换超分后当前页黑屏

### 调查与实现范围

1. 对照 NextE 图片叶组件的 `onSuperResolutionSettingChanged()`、稳定原图字段和超分任务所有权。
2. 枚举 NextN 单页、双页、连续阅读实际使用的图片叶组件，确认每条超分设置 Monitor 都覆盖到。
3. 将“超分配置刷新”与“重新加载图片源”拆开：
   - 超分配置变化时不得调用会清空 `imageSource` 的完整 `loadImage()`；
   - 保留当前已显示图片、当前页索引、缩放、裁剪和图片已加载状态；
   - 取消或作废旧超分任务，但不清空基础图片；
   - 关闭超分时恢复当前页已经解析完成的原始显示 URI；
   - 开启、切换模型或更改高度时，使用当前页已经解析完成的本地文件重新处理；
   - 新结果完成且仍属于当前页和当前设置时，才替换显示 URI。
4. 不借此重构 Reader、不调整转场、不修改 NextE。

### 静态验收

- 差异只涉及 NextN 中超分设置刷新所必需的代码。
- 三种 Reader 图片叶路径不存在仍以完整 `loadImage()` 响应超分设置变化的遗漏。
- 异步结果带有当前页、当前源和当前超分配置的有效性检查，旧任务不能覆盖新设置。
- `git diff --check`、NextN Reader 契约测试和签名构建通过。

### 237 实机验收

- 在已经显示当前大图的情况下依次验证：关闭到开启、开启到关闭、切换模型/配置。
- 单页、双页、连续阅读各至少一次。
- 每次操作从设置动作前开始连续录制，到新结果稳定后结束；不能只截最终状态。
- 全程禁止出现黑色空帧、图片源清空、页码变化、自动翻页、缩放复位或必须手动翻页才能恢复。
- 快速连续切换两次时，旧超分结果不得覆盖最终选择。

### 阶段出口

只有静态门禁和上述实机路径都通过，才允许在 NextN 形成一个仅包含问题 A 的阶段性提交。

已于 2026-09-03 完成并提交：`010a5e8 fix(reader): preserve image during enhancement changes`。

## 阶段 3：增强现有加载指示器的转场背景

### 组件设计

1. 在 NextE 与 NextN 各自现有的 `ReaderLoadingStage` 增加一个明确的布尔参数，例如
   `showTransitionBackground`；默认值为 `false`。
2. 外层全屏容器继续只负责居中和命中关系。背景、模糊、圆角和内边距只施加在包含进度条与单行文字
   的内部内容容器上，保证背景和内容使用同一布局边界并共享几何中心。
3. 无进度时单行文字显示加载状态；有进度时由百分比原位替换状态文字，不增加第二行、不预留隐藏行，
   也不设置固定高度。容器始终由同一组元素和应用间距令牌自然撑开，禁止中途跳高。
4. 圆角直接复用两边应用既有的卡片大圆角令牌：NextE 的 `ThemeConstants.RADIUS_CARD` 与 NextN 的
   `ThemeTokens.RADIUS_CARD`；不新增圆角魔法数字。背景为低不透明度中性色叠加普通背景模糊；不使用
   API 26 专有材质，不做 API 版本分支。
5. 只有缩略图转场中的现有图片加载调用传入 `true`。非转场页面和其他加载状态继续使用默认值，
   不改变现有视觉与布局。

### 视觉验收

- 在 237 上使用同一慢加载样本，连续覆盖指示器出现、无进度、进度更新和消失全过程。
- 背景与指示内容的实际布局中心重合，不以“视觉上差不多”代替坐标检查。
- 容器宽度、内边距和应用大圆角连续稳定；高度由固定的两元素结构自然决定，禁止中途跳高、文字换行
  撑高或背景晚一帧出现。
- 深色图片、浅色图片和模糊缩略图上均可辨识；背景不能接近纯黑，也不能弱到看不出圆角边界。
- NextE 与 NextN 使用同一组设计数值和同一显示条件。
- 非转场 Reader 加载页面与修改前对照一致。
