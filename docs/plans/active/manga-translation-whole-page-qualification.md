# 漫画整图路线资格验证

状态：进行中<br>
最近复核：2026-07-27<br>
范围：只评估现有 Torii 整图后端能否在真实漫画页达到 Reader 可读成图；不新增 provider、设置项、提示词参数或端侧视觉启发式。

## 要回答的单一问题

现有 Torii 模型目录中，除已经失败的 `gemini-3.1-flash-lite` 外，是否存在一个高质量模型能在真实彩色高密度页面上稳定返回可阅读的完整译图？

## 已有否决证据

设备 237、用户指定真实彩色画廊 P21：`gemini-3.1-flash-lite` 返回中文，但日文原字残留并与译文叠加，竖排溢出；画面主体虽保留，Reader 成品不可读。P45 仅验证真实 Gallery Reader 上传、回图、缓存替换，不能作为质量证据。

## 固定方法

1. 只从运行时 Torii 目录查询一次可选模型；选择一个明确高于 Lite 的候选。若目录没有这样的候选，直接得出 Torii 当前不合格，不再试填名称或穷举模型。
2. 冻结 3 张真实、文字充分的页面：P21 作为开发页，另选 2 张同类彩页作 holdout。先看原图，文字不足的页面不得发起整图请求。
3. 每页只请求一次，不改字体、prompt、context 或其他参数。每张结果逐项记录：原文残留/叠字、译文完整性、竖排 fit、非文字画面保真、请求耗时和 credits。
4. 任一 holdout 出现明显原文残留叠字、文字越界或主体画面破坏，即该候选不得成为默认整图模型；不做第二轮调参。三个页面均通过才允许提出后续产品接入/默认策略。

## 明确不做

- 不把 Torii OCR、修复或排版子接口拆进端侧；
- 不重复测试 Lite，也不靠换字体或扩 prompt 解释失败；
- 不把端侧 AOT/容器问题带入本计划；
- 不因单页看起来不错宣布整图可交付。

## 结束条件

仅以下任一结果结束本计划：

1. 一个候选通过开发页与两张 holdout，形成可复核的整图质量基线；或
2. 当前 Torii 目录没有合格候选，或候选在固定三页门任一失败，明确维持“实验路线，不作成品承诺”。
