## 1. 用户问题与第一版目标

用户希望利用已有大模型接入能力改善使用体验。当前最常见的问题是：记得收藏过某一本，
但忘记名字；同时也存在不知道从收藏里挑什么看的情况。用户对个人资料库和智能合集感兴趣，
并要求考虑 EH 搜索、收藏管理的实际限制。

第一版优先解决以下路径：

> 为选定的网络收藏建立文字目录 → 与本地收藏一起搜索 → 用已有线索找回画廊 →
> 补充私人标签或笔记 → 把有用的筛选保存为会随资料变化更新的合集。

成功的核心是找回真实画廊、减少重复整理；不以模型回答的篇幅或新建分类数量衡量效果。
普通搜索和合集不依赖模型在线。模型用于理解自然语言、建议条件和辅助排列候选。

### EH 边界

- 网络收藏仍由 EH 管理，十个分类和远端备注继续保持原用途。
- 收藏列表需按实际页面分页读取；`gdata` 用于补全已知 ID/token 的元数据，不是账号收藏导出接口。
- EH 收藏备注有长度和数量限制，不用它存储完整私人档案、合集规则或隐藏的 JSON。
- 收藏搜索支持站点定义的语法，受频率、长度和词项限制；不能把任意自然语言直接当成可靠查询。
- 远端收藏更新可能涉及画廊版本链；相似标题、其他语言版本不能自动视为同一条收藏。
- 未取得可靠字段的历史收藏时间、完整备注、版本关系标为未知，不能由首次索引时间或模型猜测补齐。

## 3. 第一版范围

### 纳入第一版的建议范围

| 能力 | 第一版交付边界 |
| --- | --- |
| 网络收藏索引 | 用户选择当前账号和站点可见的收藏范围；分批建立基础目录，补全缺失文字元数据；可暂停、恢复、刷新 |
| 本地收藏接入 | 现有本地收藏自动成为联合搜索的数据来源；不把网络索引条目自动变成本地收藏 |
| 联合搜索 | 当前账号的已索引网络收藏与本地收藏取并集；按画廊标识去重，保留来源和覆盖情况 |
| 普通检索 | 标题、作者/作品等原始标签、远端备注、私人标签、私人笔记；来源、语言、类别、页数等明确条件 |
| 自然语言辅助 | 把表达转换为可查看、可修改的条件与排序偏好；可选的小批候选重排；失败可退回普通搜索 |
| 私人资料 | 多个私人标签、一份可编辑笔记、显式阅读状态；与远端备注分别保存 |
| 阅读与下载条件 | 复用可验证的当前阅读进度和本机下载状态；显式状态支持“待看、在读、已读、搁置”，默认“未标记” |
| 智能合集 | 从当前搜索或手动条件创建；支持模型草拟条件、预览结果、命名、修改、手动加入/排除及自动重算 |
| 数据保护 | 新资料持久化、迁移和备份；纳入已支持同步提供方的用户资料合并，网络扫描进度保持设备独立 |
| 状态说明 | 区分目录覆盖与字段补全；显示最后更新、信息缺失、网络状态待确认、模型不可用 |

“纳入第一版”是供用户审阅的范围建议，不是实现承诺。同步提供方是否能承载新增数据，必须在
实施前核对；若只能先发布本地预览版，须明确注明新增资料未同步，不能默默缩减数据保护范围。

### 留给后续的能力

- 全量封面识别、正文/OCR 索引、按剧情或画面找回、向量检索。
- 自动重排 EH 十个收藏夹、批量改备注、自动取消或去重收藏。
- 跨版本自动合并、跨语言版本归并、自动补齐系列缺章。
- 专门的历史收藏检索入口、全库自动分类、个性化推荐。
- 全站自然语言探索、评论摘要、页面知识库等第 12 节扩展。
- 无人值守的长期扫描、定时远端监控与后台模型批处理。

保留已有远端收藏、搜索、下载等入口的正常行为。本文不确定视觉样式，也不授权改变现有界面。

## 4. 合并的对象与数据归属

### 同一本画廊只有一个检索结果，可以有多个来源

以 EH 画廊 ID 作为第一版合并标识，token 和访问站点作为访问资料维护，不按标题去重。
不同画廊 ID 第一版保留独立结果；有可靠版本证据时可记录关系，但不自动迁移私人资料或书签。

| 信息 | 归属与更新规则 |
| --- | --- |
| 标题、原始标签、页数等目录资料 | 从远端或已有本地记录取得，保存来源、观察时间与完整性；缺失字段不能用空值覆盖已有可靠值 |
| 网络收藏关系 | 归属于 EH 账号，记录分类编号、远端备注和最近确认状态；站点可见性及扫描覆盖分别记录 |
| 本地收藏关系 | 沿用当前应用全局本地收藏范围，由用户的加入/移除动作维护 |
| 私人标签、笔记、显式阅读状态 | 建议与现有全局本地资料一致，属于应用用户资料，不写回 EH；账号切换不应隐式复制或删除 |
| 阅读历史与进度 | 保留各自现有数据所有者，查询时关联；浏览过详情不等于读完 |
| 下载状态 | 使用本机真实下载记录；其他设备同步来的资料不能证明本机文件存在 |
| 合集规则与手动例外 | 属于用户持久资料；计算出的结果列表是派生数据 |
| 索引覆盖、请求断点与失败状态 | 属于设备、账号和站点的扫描任务；不能用于覆盖另一设备的事实 |

账号 A 与账号 B 的远端收藏状态严格隔离。联合搜索默认只带入当前账号的远端记录，另加应用已有
本地收藏；不因为切换账号而把上一个账号的远端目录混入结果。私人资料的全局范围是本稿建议，
实施前需评审其与现有本地收藏的一致性。

字段需区分“未取得”和“确认已清空”：前者不能覆盖已有资料；用户或可靠读回确认备注被清空时，
应正常更新远端备注，不以保留旧值为由阻止真实修改。私人笔记仍独立保留。

三类删除动作必须区分：

- 从合集排除：只修改该合集的手动例外。
- 取消本地收藏：只解除本地收藏关系；网络仍收藏时，联合搜索中继续存在。
- 取消 EH 收藏：经现有远端流程确认后解除对应关系；本地仍收藏时，联合搜索中继续存在。

两种收藏关系都不再存在时，退出默认“全部收藏”搜索；私人笔记和标签保留，不能被刷新或取消收藏
顺带清除。清理个人资料是单独动作。索引重建或清理缓存也不能删除这些资料。

## 5. 流程一：为网络收藏建立索引

### 首次使用

1. 用户从收藏相关入口选择“建立收藏索引”（暂定名称）。已有本地收藏无需等待此流程即可搜索。
2. 展示当前账号、站点、十个收藏分类，选择全部或部分。显示可信的可见计数；计数未知则不显示虚假百分比。
3. 说明本次建立文字目录，不下载正文，也不自动把收藏资料发给大模型；封面使用已有或常规展示缓存。
4. 用户开始后，先分页保存基础记录，再补全缺少的文字元数据。两种进度分开报告。
5. 已写入记录立即可被搜索；用户可离开页面继续使用应用。应用挂起或退出后保留进度，恢复时继续，
   第一版不承诺系统后台持续执行。
6. 完成时展示本次范围、已读取数量、待补全数量、失败项及更新时间。这里只能说“本次扫描结束”，
   不能声称是远端某个瞬间的绝对完整快照。

示例文案仅用于说明语义：

> 本地收藏可搜索。网络收藏已索引 680 条；已选范围的扫描尚未完成，另有 42 条待补全标签。

### 扫描与刷新规则

| 情况 | 行为 |
| --- | --- |
| 手动暂停 | 停止调度新请求，保存已完成页面及断点，不回滚已取得资料 |
| 网络失败或限流 | 保留目录，退避或暂停；用户可恢复，不从头清空重抓 |
| 游标失效、重复页或排序变化 | 标记本段覆盖不可靠；重新核对受影响范围、按 ID 去重，不把循环结束当作完成 |
| 在扫描中切换账号/站点 | 旧任务暂停；在途响应不能进入新账号/站点的活动结果 |
| 浏览收藏列表 | 对当前账号有效的观察可补入目录；仅浏览过的页面不能标为完整覆盖 |
| 在 NextE 内成功新增/移动/取消远端收藏 | 用已确认操作更新对应关系；失败或结果未知不伪造成功 |
| 在网页或其他客户端中改动 | 通过后续读取发现；只刷新最新页无法发现所有旧条目的变化 |
| 用户要求刷新某收藏夹 | 更新所选范围；未扫描范围保持原记录和原更新时间 |
| 用户取消某范围的持续索引 | 停止后续获取；旧数据不自动删除，标为未继续维护，并允许单独清理 |

扫描数据应在本地展示屏蔽前取得；展示、模型候选选择仍遵守屏蔽设置。远端设置、权限和站点可见性
仍可能让扫描不完整，不能因某次没出现就自动标记“已取消收藏”。单夹扫描尤其不能把移动到另一夹
误判成取消。未确认条目保留最后已知状态并标注待确认，只有可靠读回或已确认的用户操作才能落定变化。

目录记录“首次收录时间”“最后观察时间”；没有可靠来源的 EH 收藏时间保持未知。
准确收藏日期检索不作为第一版保证能力。

## 6. 流程二：网络索引与本地收藏联合搜索

### 搜索范围与合并

建议在搜索中增加明确的“全部收藏”范围，与现有远端收藏搜索区分；最终入口布局另行评审。

```text
当前账号的已索引网络收藏 ─┐
                         ├─ 按画廊 ID 合并 → 关联私人资料 → 应用展示过滤 → 查询与排序
现有本地收藏 ───────────┘
```

- 默认按最后已知收藏关系搜索，并标注远端更新时间及待确认状态；不假装每次搜索都实时访问 EH。
- 同一本同时属于两种收藏，只显示一条结果，注明“本地 + 网络 · 收藏夹名称”。
- 可切换“本地收藏”“当前账号网络收藏”或选定网络收藏夹。收藏夹按编号关联，改名不使规则失效。
- 某画廊即使同时有本地收藏，选择“网络收藏夹 A”时仍须满足 A 的远端关系。
- 没有登录、离线或未建网络索引时，本地搜索仍可使用；不能将已退出账号的远端目录自动加入默认结果。
- 搜索资料不等于已下载图片；只有真实离线文件可用时才表示能够离线阅读。

### 普通搜索

1. 用户输入标题片段、作者、标签或备注关键词。
2. 在标题、保留命名空间的原始标签及已知译名、远端备注、私人标签和笔记中匹配。
3. 用户可增加来源、语言、类别、页数、显式阅读状态、本机下载状态等条件。
4. 结果附匹配依据，如“私人笔记包含……”“作者标签匹配”，进入现有画廊详情或阅读流程。
5. 通过有界查询与分页展示结果，不要求每次把全部资料加载进 UI 内存。

远端备注与私人笔记分别显示和编辑，不能因为文案相似而双向覆盖。未知字段不满足严格条件；
界面说明“部分条目资料不足”，不能将缺失标签解释成确定不属于某类型。

### 自然语言找回

例子：

> 找我收藏过的一本中文短篇，好像是作者 A 的，备注里写过构图不错。

1. 用户主动选择自然语言辅助，并使用独立的收藏助手模型绑定。
2. 模型提出可解释查询：中文是筛选条件；“短篇”和“好像作者 A”先作为排序偏好；
   “构图不错”检索备注/笔记及合理的相近表达。具体页数阈值必须可见、可修改。
3. 应用校验条件支持范围，在本地目录召回真实候选。普通搜索不等待模型才能显示可用结果。
4. 可选地把有数量上限的候选文字资料交给模型重排；只接受候选集合内的 ID。
5. 用户说“作者可能记错了”，更新当前搜索的偏好；不修改画廊作者标签或收藏记录。
6. 找到目标后，可添加私人笔记“以后按构图参考找”，改善下次检索。

没有封面分析就不声称匹配“蓝色封面”；没有正文索引就不声称匹配剧情。
不支持的线索明确列出，让用户看候选封面继续辨认，而不是生成确定的内容描述。
正文、备注、标题都是待检索数据，不能作为模型执行动作的指令。

### 找不到时的处理顺序

1. 先显示实际覆盖：本地条目正常，哪些网络收藏夹没索引，哪些条目缺资料。
2. 提供放宽模糊条件、改用关键词、补全所选范围的选择，避免直接断言“没有收藏”。
3. 用户可显式选择“到 EH 收藏补搜”。仅发送 EH 支持的条件，显示实际搜索条件与范围，限制请求次数。
4. 远端结果补入当前账号的目录，与本地结果去重；私人资料条件仍由本地执行，缺数据时注明无法判定。
5. 一次补搜只证明该查询下观察到的结果，不会让整个收藏夹突然成为“已完整索引”。

模型失败、输出无效、源未配置或取消请求时，保留当前查询与结果，退回普通搜索。
首次模型使用说明会发送哪些文字；不发送 EH Cookie、认证信息，也不默认上传整个收藏库。

## 7. 流程三：创建智能合集

### 从搜索结果创建（主要路径）

1. 用户完成一次“全部收藏”搜索，例如：中文、私人标签“构图参考”、显式状态为“待看”。
2. 选择“保存为智能合集”，预览合集名称、来源范围及远端账号、规则、排序、当前匹配数量和资料覆盖。
3. 若搜索含模糊偏好，明确决定它仅用于排序，还是转换成有明确阈值的筛选；不直接保存含糊自然语言作为规则。
4. 用户命名“待看参考作品”，保存。保存的是规则，不是当前结果快照。
5. 打开合集时，本地按同一规则计算当前结果；无需再次请求模型或扫描远端。

含网络来源的合集保存明确的账号绑定。切换到另一账号后，不悄悄将规则中的收藏夹套到新账号：
提示原账号网络来源当前不可用；混合来源合集仍可计算本地部分，并标明结果不完整。
重新绑定账号需要编辑与预览。仅本地来源的合集不依赖 EH 登录。

### 手动创建与模型辅助创建

- 手动创建：先选来源，再添加支持的条件、名称和排序，预览后保存。
- 模型辅助：用户说“建一个已下载、我标记待看的中文收藏合集”，模型生成同一套结构化条件，
  用户检查后保存。模型不能创建当前查询引擎不支持的隐藏条件。
- 模型推测“剧情好”“画风清爽”时，第一版可建议使用相应私人标签，但不能假装已经分析过每本。

### 第一版规则能力

支持来源选择、字段条件、明确的全部满足/任一满足组合、排除条件与排序；限制规则复杂度，
不开放任意代码、模型生成 SQL 或每次运行时重新解释的提示词。具体操作符随实现评审固定。

推荐示例：

| 合集 | 规则 | 需要特别说明 |
| --- | --- | --- |
| 待看中文 | 全部收藏 + 中文 + 显式待看 | 未标记不等于未读 |
| 构图参考 | 全部收藏 + 私人标签“构图参考” | 标签由用户维护，模型建议需确认 |
| 离线待看 | 全部收藏 + 本机已下载 + 显式待看 | 不同设备结果可以不同 |
| 作者小书架 | 指定来源 + 某些作者标签 | 缺作者信息的条目不能当作已核实不匹配 |

现有 EH 查询型自定义配置继续保留。第一版的新智能合集以本地资料库执行为主，不额外引入自动轮询
EH 的第二套合集系统，也不将每个本地合集映射成一个 EH 收藏夹。

## 8. 智能合集如何更新、调整与删除

### 自动更新的是结果，规则只在用户编辑时改变

| 触发事件 | 结果变化 |
| --- | --- |
| 新的网络收藏被索引，或本地新增收藏 | 若符合来源和条件，下次计算时出现 |
| 补全语言、作者或页数 | 重新判断依赖这些字段的条件，可能新增或移出 |
| 私人标签、笔记或显式状态改变 | 相关合集重新计算 |
| 下载完成或本机文件被删除 | 使用下载条件的合集更新；不改变收藏关系 |
| 收藏移动到其他网络夹 | 基于指定夹的合集在确认移动后更新 |
| 用户确认取消收藏 | 不再满足来源时退出；若另一收藏来源仍满足则保留 |
| 远端暂时不可访问或扫描不完整 | 保留最后已知结果并标注过期/待确认，不批量清空 |
| 修改合集规则 | 预览变化后保存，使用新规则重算 |
| 模型或模型源改变 | 不改变已保存规则，不自动重新分类 |

数据变化后标记相关合集待重算，打开或刷新时按当前资料计算。正在浏览时先保留列表位置并提示有更新，
由刷新接纳新结果，避免条目突然移动。应用恢复前台后检查本地数据版本；这不等于自动发起全网扫描。

### 手动加入和排除

推荐计算方式：

```text
合集结果 = ((在来源范围内满足规则的画廊 ∪ 在来源范围内手动加入的画廊) − 手动排除)
           再应用当前账号可见性及用户屏蔽规则
```

- 手动加入可以越过普通内容条件，不能绕过账号隔离、选定来源或屏蔽规则。
- 手动排除优先于规则和手动加入；重新加入时清除排除标记，不留下相互矛盾的状态。
- 从结果移除时，语义是“从该合集排除”，不取消任何收藏；可撤销并在例外列表中管理。
- 手动加入项后来不再满足来源时，保留例外记录但不显示；再次满足来源可恢复出现。
- 修改规则或来源时保留手动例外，并在预览中说明哪些例外将生效或暂不适用；清空例外是独立选择。
- 删除合集只删除其规则及例外，不删除画廊、私人笔记、标签、下载或 EH 收藏。

## 9. 一个完整使用例子

以下画廊、数量与时间均为示例，不是用户真实收藏数据。

1. 用户有 120 本本地收藏，选择为网络收藏夹 A、B 建立目录。
2. 目录已读取 400 本，其中 30 本也在本地收藏；按 ID 合并后是 490 本可搜索记录。
   该数量不包含未读取条目，实际可见结果还受屏蔽与查询条件影响。
3. 用户输入“中文，作者像是 A，记得写过画风不错”，本地检索返回候选并说明匹配线索。
4. 目标画廊同时显示本地和网络来源。用户确认后添加私人标签“构图参考”，标记“待看”。
5. 用户将“全部收藏 + 构图参考 + 待看”保存为“周末参考”。
6. 后续另一条收藏获得相同私人标签与状态，刷新合集后自动进入。
7. 用户把第一本标为已读，它退出该合集，但仍保留在本地和网络收藏中。
8. 若用户希望已读的这一本继续保留，可手动加入，预览标明“手动加入，不满足待看条件”。
9. 在另一设备打开同一合集时，使用同步到的规则与私人资料及该设备的目录计算；缺失的远端目录
   明确提示补建。不能把结果数量不同直接当作同步失败，也不能隐藏资料尚未同步的实际失败。

## 10. 实现边界、持久化与成本

### 建议的职责划分（尚未定具体类名和表结构）

- EH 读取层：复用现有鉴权、请求、分页和解析能力，暴露可供索引使用的观察数据；不恢复被拒绝的协议方案。
- 索引任务：拥有账号/站点/范围、断点、完整性和补全进度；批次落盘，去重，有界重试与背压。
- 资料仓库：保存元数据、关系、私人资料、合集规则；分别明确更新与删除语义。
- 本地查询层：确定性条件、排序、分页和匹配解释，为搜索和合集共用。
- 模型适配：复用共享源凭据，新增独立消费者绑定，校验查询计划及候选 ID；不直接执行数据库或远端写入。
- 展示层：复用现有导航、列表与详情能力；本稿不指定新的自绘控件、布局或样式。

遵循 [架构](../architecture.md) 与 [EH 契约](../eh-integration-contract.md)。上述为讨论中的职责建议，
不是已建立的新模块，也不据此扩展 Reader 的工作范围。

### 持久数据与派生数据

| 数据 | 第一版建议 |
| --- | --- |
| 私人标签、笔记、显式状态、合集定义及手动例外 | 必须持久化、进入备份与同步；包含删除记录与冲突处理，不能用缓存替代 |
| 这些资料引用的最小画廊信息 | 一并提供必要标识及可展示快照，避免另一设备只有无法识别的 ID；快照不证明远端仍收藏 |
| 大范围网络目录及扫描进度 | 每台设备独立维护，按账号/站点记录来源和时间；第一版不将全量目录当权威跨设备状态同步 |
| 检索索引与模型排序缓存 | 可重建；绑定资料版本和查询身份，清理不影响用户资料 |
| 已有本地收藏、历史、进度、下载 | 沿用现有所有者，查询关联；新增功能不能重定义或覆盖其同步语义 |

新资料不能直接继承本地收藏 `lastViewTime` 作为所有字段的冲突时钟。需要逐类定义更新版本、
删除与恢复行为；并发笔记编辑保留可恢复副本，不能无提示丢弃正文。具体合并协议需与现有同步设计评审。

### 成本控制

目录建立、普通检索、合集计算默认不调用模型。元数据按缺失情况补充，图片/正文分析不在第一版。
模型调用分查询理解与可选候选重排，均有明确输入上限、取消和失败退路。候选重排不能修复未召回的数据，
因此效果评估需区分覆盖不足、召回遗漏与排序不佳。

收藏数量、网络响应速度及真实字段覆盖尚未知，暂不承诺扫描耗时、存储量或模型费用。以后应以小样本实测
每页请求数、补全比例、条目占用和模型输入量再估算，而不是按画廊总数直接报一个时间。

## 11. 第一版验收场景与实施前问题

以下是未来实现的验收建议，本次只检查文档，没有执行这些测试。

| 场景 | 预期 |
| --- | --- |
| 同一本分别在本地与网络收藏 | 联合结果只有一条，显示两种来源，移除其中一个来源不会错误消失 |
| 只索引部分网络收藏 | 本地仍正常搜索；页面清楚说明网络覆盖，不宣称“全库无结果” |
| 扫描暂停、断网、退出并恢复 | 已写入资料可用，恢复不重复条目，异常分页不伪报完整 |
| 收藏被屏蔽、换夹或站点不可见 | 不因过滤/缺席误判取消，正常展示继续遵守屏蔽 |
| 账号切换及在途响应返回 | 不混入其他账号的网络收藏、备注或候选 |
| 模型不可用或返回不存在的 ID | 不展示虚构画廊，保留普通检索与原结果 |
| 模糊记忆中作者或页数记错 | 用户能放宽偏好，硬筛选条件可见，返回可核实候选 |
| 规则创建、手动加入与排除、编辑、删除 | 优先级符合第 8 节；不产生 EH 写入，不取消收藏 |
| 新收藏、标签修改、已读标记、下载状态变化 | 相关合集在刷新后变化，规则本身不漂移 |
| 元数据或阅读状态缺失 | 明确未知，不等同于“没有此标签”“未读”或“未收藏” |
| 备份恢复与多设备同步 | 私人资料、规则、例外和删除状态可恢复；不把他机扫描缺席当删除 |
| 索引重建或缓存清理 | 私人资料及合集定义保留 |

效果评估采用用户提供的真实找回案例：记录原来使用的线索、目标是否被索引、是否进入候选、
是否在首屏可辨认，以及普通搜索与模型辅助的差异。样本规模和量化目标待用户收藏量及样本确定。

实施前仍需确定：

1. 用户收藏量、常记住的线索、是否经常在其他客户端编辑收藏。
2. 真实页面能批量取得的备注、分类、时间等字段，以及表/里站可见范围差异。
3. 索引期间远端变化、游标恢复、权限失败及收藏迁移的验证方式。
4. 私人资料采用应用全局范围的产品选择，以及新增数据在各同步提供方的可用性。
5. 最终入口与原搜索入口的关系；任何界面与样式改动须单独确认范围。
6. 模型源对结构化查询任务的实际适配效果、失败率与用量限制。

## 12. 收藏之外与后续扩展的玩法

以下均为候选想法，未纳入第一版，也不构成开发或后台任务授权。优先用现有可靠数据解决问题，
需要视觉/正文理解的方向另行评估数据获取、成本与效果。

| 方向 | 具体使用方式 | 可复用基础与新增依赖 | 关键边界 |
| --- | --- | --- | --- |
| 全站自然语言搜索 | “帮我转成 EH 支持的搜索条件”，预览后搜索、继续收窄 | 查询理解、标签词典；需验证站点语法与限制 | 不生成不受支持的筛选，不无限自动试搜 |
| 从收藏重新发现 | “从我的收藏里挑三本短一点、标记待看的” | 资料库、显式状态与候选排序 | 给出具体推荐依据，用户可排除；不从一次点击认定长期偏好 |
| 批量整理旧收藏 | 先试整理一小批，确认私人标签建议，再处理下一批 | 完整目录、标签建议和批次预览 | 记录建议与确认的区别；不自动改 EH 收藏夹或覆盖备注 |
| 收藏理由助手 | 收藏时写一句“以后参考配色”，提议私人标签和笔记 | 私人资料与文本理解 | 保存用户原话；不能替用户编造喜欢的理由 |
| 系列与版本导航 | 查看已知顺序、不同版本、可能的新版本 | 版本链字段、标题与标签，必要时人工确认 | “未知是否有下一本”不能写成“缺章”；跨语言不自动合并 |
| 封面印象找回 | “封面偏蓝、两个人物”，在已选范围寻找 | 封面视觉索引、多模态模型或本地视觉能力 | 识别结果会出错；普通搜索不强制上传图片 |
| 页面书签资料库 | 对某页写“构图参考”，之后按笔记查到页码 | 画廊/页码书签、笔记，后续可加 OCR | 版本变化需重新定位，不能自动把旧页码套到新版本 |
| 评论信息提取 | 从已加载评论中整理有关缺页、版本、翻译的反馈 | 评论与翻译能力、带来源的摘要 | 区分评论者说法与已验证事实，提供原评论入口和覆盖范围 |
| 系列术语与译名记忆 | 同系列沿用用户确认的名字、称呼和词汇 | 现有翻译文档、术语及用户修订 | 遵循现有漫画翻译设计，不能由收藏项目另开翻译实现队列 |
| 阅读回顾与私人短评 | “整理我这周的阅读笔记，列出还想继续看的” | 真实阅读记录、用户笔记 | 历史不完整时说明范围，不凭翻页推断情绪或评价 |
| 个人资料问答 | “我在哪些作品里记过这个作者的构图？” | 私人笔记、标签与检索 | 回答链接真实画廊或笔记；无证据时明确未找到 |
| 下载安排助手 | “给离线阅读准备几本，控制在可用空间内” | 下载状态、文件大小与收藏优先级 | 先提出清单；大小未知要保留余量，不擅自下载、删除或消耗付费资源 |
| 多条线索的阅读续接 | “继续上次看了一半的那个系列” | 阅读进度、历史与系列关联 | 多个候选时展示供选择，不能把详情浏览等同于阅读 |
| 内容内释义与文化背景 | 选择一段文字，解释词义、典故或翻译差异 | 用户选中文本、现有翻译上下文；必要时外部来源 | 区分原文信息与补充解释，避免无来源编造背景 |
| 个人专题清单 | 将多本作品、页面笔记整理成可编辑的主题清单 | 合集、笔记、可选导出 | 默认整理个人文字与链接，不自动外发内容或发布清单 |

建议后续按真实使用问题选择方向：找回失败主要来自封面记忆，再评估视觉索引；收藏后仍不知道看什么，
再做重新发现；私人笔记增加后，再扩展页面资料与问答。不要为了调用模型而把确定性的筛选和排序变成模型任务。
